Features

One daemon. Every GitHub chore.

Heimdallm is a Go daemon plus a Flutter desktop / web app and a CLI/TUI. It polls GitHub on your behalf and runs three pipelines in parallel: PR reviews, issue triage, and auto-implement.

🤖

Automatic PR reviews

Polls review-requested:@me, runs your AI agent on the diff, and submits a proper GitHub review under your account. REQUEST_CHANGES on high severity, APPROVE otherwise.

🧭

Issue triage & refinement

Classifies issues by label — review_only, refinement, develop, skip, blocked — and walks them through triage → refinement → development with a state machine you control.

🛠️

Auto-implement

For develop-track issues the agent creates a branch, commits the change, and opens a PR against your default branch — hardened against prompt injection.

🔗

Issue dependencies

Declare blockers with a ## Depends on section or GitHub's native sub-issues. Heimdallm holds the issue until every prerequisite closes, then auto-promotes it.

🧠

Your AI, your rules

Pick Claude, Gemini, Codex, or OpenCode — globally or per repo. Plug in your subscription token or an API key. Pass custom CLI flags.

✍️

Custom prompts

Review profiles managed from the web UI at /agents. Placeholders for {diff}, {title}, {author}, {link}, {comments} and full template overrides.

🏷️

Topic-based discovery

Tag a repo with a GitHub topic and it joins the monitored set on the next discovery cycle — no config edits, no daemon restart. Persists across restarts even before its first PR.

⚡

Parallel polling

Per-repo concurrency on Tier 2 polling, per-execution git worktrees so concurrent pipelines don't fight over the working tree, and an internal liveness watchdog.

🔁

Survives rename / archive

Detects when GitHub renames a repo or org and propagates the new slug across config and stored state. Auto-purges archived repos from the monitored list.

🖥️

Native apps + Web UI + CLI

Menu-bar app on macOS, native desktop on Linux (.deb, .rpm, AppImage), a Flutter Web dashboard for headless deploys, and a Bubble Tea CLI/TUI via Homebrew.

🐳

Docker mode

make up brings up the daemon and the web UI on port 3000. All four AI CLIs bundled. Configure via env vars or a live-editable config.toml.

🔒

Safe by default

Hides PRs you authored from the review queue, refuses dangerous skip-perms flags over the HTTP API, and runs every AI agent in non-interactive mode.

"Migration from kubernetes-labeled runner to generic self-hosted runner with kubectl port-forward for registry access. The approach is functional but has reliability and security concerns around the port-forward lifecycle and kubeconfig handling."

🔴 .github/workflows/docker-publish.yml:138 — Port-forward process (PF_PID) is only killed on the happy path. If docker push fails, the port-forward process leaks.
🔴 .github/workflows/docker-publish.yml:121 — KUBE_CONFIG secret is base64-decoded and written to ~/.kube/config. If the job crashes before cleanup, credentials persist on the runner.
🟡 .github/workflows/docker-publish.yml:128 — LOCAL_PORT is defined as a string env var but used in numeric contexts. Two concurrent builds will race on port 5050.

Installation

Up and running in minutes

1

Download

Grab the latest DMG from GitHub Releases.

⬇️ Download .dmg
2

Drag to Applications

Open the DMG and drag Heimdallm to the Applications folder.

3

Remove quarantine

Run once in Terminal — macOS security requirement for unsigned apps:

xattr -cr /Applications/Heimdallm.app

Requires macOS 13+ (Apple Silicon or Intel) · gh CLI authenticated · at least one of Claude / Gemini / Codex / OpenCode CLIs installed on the host

1

Download .deb

⬇️ Download .deb
2

Install

sudo dpkg -i heimdallm_*.deb
sudo apt-get install -f -y
3

Launch

heimdallm

Or find it in your application launcher.

Installs to /opt/heimdallm/ · Dependencies: libgtk-3, libayatana-appindicator, libsecret · Token via GNOME Keyring or gh auth token

1

Configure

cp docker/.env.example docker/.env
# Fill in GITHUB_TOKEN + at least one provider key
2

Start daemon + web UI

3

Open the dashboard

curl http://localhost:7842/health

Then visit http://localhost:3000 in your browser — Flutter web UI on port 3000, daemon API on 7842.

Image: ghcr.io/theburrowhub/heimdallm:latest · all four AI CLIs bundled · runs as non-root · web UI waits for the daemon's healthcheck before accepting traffic

1

Install

brew install theburrowhub/tap/heimdallm-cli

Or grab a heimdallm-cli_* archive from Releases.

2

Point at a running daemon

export HEIMDALLM_HOST=http://localhost:7842
export HEIMDALLM_TOKEN=<your token>

Defaults to localhost — skip these if you're on the same host. See the configuration guide for token setup.

3

Launch the dashboard

heimdallm-cli dashboard

Or: prs, issues, repos, review-pr, follow, config, stats.
